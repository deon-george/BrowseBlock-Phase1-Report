2.1 XGBoost-Based URL Phishing Detection Method With Cross-Dataset Validation, 2026
The paper [1] by Milosz Misiek and Tomasz Hyla presents a machine-learning approach for detecting phishing URLs using XGBoost. The study addresses the difficulty of identifying malicious URLs that resemble legitimate web addresses and the challenge of maintaining detection accuracy when the model is evaluated on datasets different from those used during training. The authors emphasize that URL characteristics vary across datasets, which can affect the generalization ability of phishing detection models.

The proposed method uses Python-based feature extraction to derive URL characteristics, including lexical features, DNS and network information, security-related attributes, domain reputation, and redirect behaviour. The study extracts more than 90 candidate features and applies feature selection to identify characteristics that remain useful across datasets. An XGBoost classifier is then evaluated using three datasets and compared with neural-network approaches. The paper reports 90.7% accuracy on its custom dataset and 77.8% average accuracy across three independent test datasets. These results highlight the importance of feature selection and cross-dataset evaluation.

BrowseBlock adopts the use of XGBoost for URL phishing classification and feature-based URL analysis. The extracted URL characteristics are supplied to the trained classifier to determine whether a destination appears legitimate or suspicious. The study's emphasis on cross-dataset validation is also relevant when evaluating the BrowseBlock model against previously unseen URLs. For QR-code phishing, BrowseBlock adds a separate decoding stage that extracts the embedded URL and sends it through the same URL-analysis pipeline; QR decoding itself is not the principal method proposed in this paper. 2.2 Classification of Phishing Email Using Random Forest Machine Learning Technique, 2014
The paper [2] by Andronicus A. Akinyelu and Aderemi O. Adewumi investigates the use of machine learning to classify phishing emails. It addresses the limitations of traditional email-filtering methods, which may fail to recognize newly developed phishing patterns because attackers frequently change the wording and structure of their messages. The research aims to identify useful email characteristics that can distinguish phishing messages from legitimate messages while reducing the number of features required for classification.

The proposed approach extracts phishing-related features from a dataset of 2,000 emails and converts them into feature vectors for machine-learning classification. The authors use the Random Forest algorithm and evaluate different feature combinations, including a reduced set of eight prominent features. The paper reports a classification accuracy of 99.7% for its evaluated model. This result reflects the dataset and evaluation procedure used in the study and should not be assumed to represent the accuracy of every phishing detection system.

BrowseBlock adopts Random Forest as the initial email phishing-screening technique. The classifier evaluates available email features and identifies messages that require further analysis. BrowseBlock extends this approach by examining URLs extracted from email content, incorporating SPF, DKIM, and DMARC results when available, and using RAG with an LLM for deeper contextual analysis. These additional stages are part of BrowseBlock's proposed hybrid pipeline rather than technologies introduced by the Random Forest paper. Email Phishing.pdf

2.3 Detecting DOM-Sourced Cross-Site Scripting in Browser Extensions, 2017
The paper [3] by Jinkun Pan and Xiaoguang Mao investigates DOM-sourced Cross-Site Scripting vulnerabilities in browser extensions. The authors explain that extension scripts can interact with webpage content and may possess privileges beyond those available to ordinary webpage scripts. When attacker-controlled webpage data is processed unsafely by an extension, the data may cause malicious script execution or unauthorized access to protected resources. The research focuses on identifying such vulnerabilities, particularly in user scripts associated with the Greasemonkey browser extension.

The authors propose a hybrid analysis framework with two phases. The first phase performs lightweight static analysis using text filtering and an Abstract Syntax Tree parser to identify potentially vulnerable code. The second phase applies dynamic symbolic execution together with a shadow DOM component and constraint-solving techniques to investigate candidate vulnerabilities. The paper reports the discovery of 58 previously unknown DOM-sourced XSS vulnerabilities in Greasemonkey user scripts. The results demonstrate the usefulness of combining lightweight source analysis with deeper investigation of potentially unsafe execution paths.

BrowseBlock adopts the concept of examining suspicious data flows between untrusted webpage inputs and potentially dangerous JavaScript operations. The XSS module can inspect accessible scripts and identify indicators involving sources such as URL parameters and sinks such as unsafe DOM manipulation functions. The paper provides a reference for more advanced static and dynamic analysis techniques, although BrowseBlock should only claim to implement AST-based analysis, symbolic execution, or shadow DOM analysis if those techniques are actually present in its implementation. cross site scripting.pdf

2.4 Hidden Path: Understanding the Intermediary in Malicious Redirections, 2022
The paper [4] by Yuwei Zeng and co-authors examines how attackers use intermediary websites and redirect chains to conceal malicious destinations. Malicious redirects can make a user's navigation path more difficult to understand by routing the browser through several domains before reaching the final page. Attackers may also use delays, fabricated user interactions, or visitor characteristics to avoid detection by conventional security checks. The study investigates the mechanisms used in these redirection campaigns and the role played by intermediate domains.

The researchers develop an iterative framework that uses a bipartite graph-based method to discover domains potentially associated with malicious redirections from real-world DNS traffic. They then use a Chrome-based crawler to visit suspicious domains and reconstruct redirect chains from browser performance logs. The analysis examines different redirect mechanisms, including HTTP-, HTML-, and JavaScript-based navigation. The paper also identifies redirection fluxing, in which randomness is introduced into the redirect process to make malicious destinations harder to track.

BrowseBlock adopts the concepts of monitoring navigation changes, examining suspicious redirect chains, and assessing the final destination using URL analysis. The redirect module can evaluate the requested URL and subsequent destinations, where the required navigation information is available, and submit suspicious destinations to the XGBoost-based URL detector. The paper's graph-based mining of DNS traffic and large-scale crawling framework are reference techniques; they should not be described as implemented BrowseBlock components unless they have been developed separately. html_js Redirect.pdf

2.5 Implementation of Extension for Browser to Detect Vulnerable Elements on Web Pages and Avoid Clickjacking, 2016
The paper [5] by Dipti Pawade, Abhilasha Lahigude, Divya Reja, and Era Johri presents ClickProtect, a browser extension designed to identify webpage elements that may be vulnerable to clickjacking. Clickjacking occurs when a user is tricked into clicking an element different from the one they intended to select. The paper examines techniques such as invisible iframe overlays and fake cursors that can conceal the actual target of a user interaction. Its objective is to detect suspicious elements and warn the user before an unsafe interaction takes place.

The proposed system consists of a revealing unit and an extenuation unit. The revealing unit inspects webpage source code and examines clickable elements, including buttons and hyperlinks, for properties such as visibility and cursor behaviour. The extenuation unit responds to suspicious elements by displaying a warning and making hidden components visible so that the user can make a more informed decision. The paper demonstrates how browser-level inspection and warning mechanisms can help address attacks involving deceptive interface elements.

BrowseBlock adopts the concepts of inspecting accessible webpage elements for suspicious visibility, overlay, and interaction indicators and warning the user when the findings are concerning. These checks contribute to its clickjacking detection module, which can present the supporting evidence through the extension popup and dashboard. Since legitimate websites also use iframes and overlays, these indicators should be combined with contextual checks rather than treating every iframe or invisible element as proof of an attack. 2.6 Analyzing In-Browser Cryptojacking, 2024
The paper [6] by Muhammad Saad and David Mohaisen investigates in-browser cryptojacking, a threat in which a webpage executes JavaScript that uses a visitor's computing resources to mine cryptocurrency without appropriate consent. Unlike conventional malware that requires users to install a separate executable program, in-browser cryptojacking can operate directly through scripts loaded by a webpage. This can consume CPU resources, drain device batteries, and affect normal system performance. The study examines the characteristics and impact of these attacks to improve their detection.

The researchers combine static and dynamic analysis to examine cryptojacking scripts. Static analysis extracts code-related features, while dynamic analysis investigates the impact of mining activity on system resources, including CPU usage and battery consumption. The paper evaluates supervised machine-learning algorithms such as Logistic Regression, Linear Discriminant Analysis, k-Nearest Neighbours, Support Vector Machines, and Random Forest to distinguish cryptojacking scripts from benign and other malicious JavaScript samples. The study also investigates browser communication and the economic feasibility of cryptojacking as an alternative to online advertising.

BrowseBlock adopts the concepts of static JavaScript inspection, extraction of suspicious script characteristics, and machine-learning-based classification for its cryptojacking detection module. These techniques can help identify scripts associated with unauthorized browser-based mining. Resource-usage indicators may also be useful when the required information is available, but CPU consumption alone cannot prove that cryptojacking is occurring. BrowseBlock's detection claims should therefore reflect the script indicators and runtime information actually accessible to its browser extension. Cryptojacking.pdf

2.7 Hidost: A Static Machine-Learning-Based Detector of Malicious Files, 2016
The paper [7] by Nedim Šrndić and Pavel Laskov introduces Hidost, a static machine-learning system for detecting malicious files. The research addresses the difficulty of identifying malware hidden inside document formats such as PDF and SWF. These files are commonly used for legitimate purposes, but their complex internal structures can also be exploited to conceal malicious content through obfuscation, encoding, or manipulation of document elements. The paper aims to improve detection while avoiding the execution-based analysis that can make some malware-scanning methods slower.

Hidost combines information about a file's logical structure with its content to generate features for machine-learning classification. It uses static analysis to examine the file without executing it and was evaluated on datasets containing approximately 440,000 PDF files and 40,000 SWF files. Its design uses structural information to characterize files and improve the detection of malicious documents. The reported experiments showed strong detection performance, particularly for malicious PDF files, compared with the evaluated antivirus engines.

BrowseBlock adopts the concepts of static file analysis, file-structure and content feature extraction, and machine-learning-based malicious-file classification. These methods can be used to assess supported downloaded files without executing them. The proposed BrowseBlock file pipeline can combine static features with SHA-256 hash-reputation checks and a trained classifier, if those components are implemented. SHA-256 matching is an additional reputation mechanism; it is not the central technique introduced by Hidost. MaliciousFileDownloads.pdf

2.8 When Push Comes to Ads: Measuring the Rise of (Malicious) Push Advertising, 2020
The paper [8] by Karthika Subramani and co-authors examines the use of web push notifications to deliver advertisements, including malicious advertising campaigns. Web push notifications allow websites to send messages to users even when the original webpage is no longer in the foreground. Although notifications support legitimate applications, attackers can exploit them to distribute deceptive advertisements and direct users to scam pages. The study investigates the prevalence of malicious push advertising and the limitations of traditional ad-blocking and URL-filtering techniques.

The authors develop PushAdMiner, a system for collecting and analyzing web push notifications. They use an instrumented Chromium-based browser to inspect service-worker behaviour and build a crawler that visits websites, registers for notifications, and collects messages. The system groups related notifications into advertising campaigns and examines their destinations to identify suspicious activity. The researchers collected 21,541 web push notifications and identified 5,143 advertisements across 572 campaigns. They reported that 51% of the collected push advertisements were malicious and found that traditional ad blockers and URL filters were often unable to block them.

BrowseBlock adopts the concepts of examining browser notification content, assessing notification destinations, and identifying suspicious links or notification-related indicators. These findings inform the browser-notification scam module, which can warn users about suspicious notification behaviour and present supporting information through the extension. PushAdMiner was designed primarily for collecting and measuring push-advertising campaigns rather than providing a complete real-time blocking classifier. BrowseBlock therefore adapts the detection insights instead of claiming to implement the entire PushAdMiner framework. Browser Notification Scams.pdf

2.9 CPDetector: Automated Detection of Excessive Permissions in Chrome Extensions, Preprint
The paper [9] by Xiaoyu Cheng and co-authors investigates the security risks associated with browser extensions that request more permissions than their functionality appears to require. Extensions use browser APIs to perform tasks such as accessing tabs, cookies, browsing history, and webpage content. Excessive permissions can expose sensitive information and increase the potential for unauthorized data access. The paper addresses this problem by proposing a framework that evaluates the relationship between declared permissions and the APIs used by browser extensions.

The authors introduce CPDetector, which extracts permission information from an extension's manifest.json file and analyzes its JavaScript code to identify API calls corresponding to browser permissions. The extracted information is used to compare declared permissions against permissions inferred from the extension's implementation. The framework also introduces PermissionGuard, a browser extension designed to alert users about excessive permissions. The paper reports analyzing 199,058 Chrome Web Store extensions and identifying 98,072, or 49.3%, as requesting excessive permissions according to its methodology. The uploaded version is identified as a preprint that has not been peer-reviewed.

BrowseBlock adopts the principle of least privilege and permission-related risk assessment for its browser-extension-abuse module. Accessible extension metadata, declared permissions, and known suspicious indicators can help identify potentially risky extension configurations. However, a standard browser extension does not automatically have unrestricted access to the internal code or runtime behaviour of every other installed extension. BrowseBlock must therefore limit its claims to information available through its implemented browser APIs or any explicitly developed extension-analysis mechanism.

2.10 A Login Page Transparency and Visual Similarity-Based Zero-Day Phishing Defense Protocol, 2025
The paper [10] by Gaurav Varshney, Akanksha Raj, Divya Sangwan, Sharif Abuadbba, Rina Mishra, and Yansong Gao proposes a phishing detection and prevention protocol designed to protect users from fraudulent login pages. The research focuses on phishing websites that imitate legitimate authentication pages to deceive users into entering sensitive information, such as usernames and passwords. The authors identify limitations in traditional approaches, including URL blacklists and heuristic detection, which may fail to identify newly created phishing pages. The paper introduces the concept of Page Transparency, which aims to verify the legitimacy of login pages before allowing them to be displayed to users.

The proposed approach uses a Public Log Server (PLS) to maintain records of legitimate login pages and cryptographic proofs to verify whether a page has been registered. It also incorporates a visual page-matching mechanism using a Siamese Network Model (SNM) to compare login pages and identify deceptive pages that closely resemble legitimate ones. A custom HTTP Page Transparency header is introduced to facilitate verification on the client side. The authors developed a Chrome extension named AntiPhish to demonstrate the proposed mechanism. Their evaluation includes credential-requiring pages associated with 91 brands, comprising 2,325 phishing pages, 115 legitimate pages, and 50 previously unseen legitimate pages. The study combines login-page verification, cryptographic proofs, and visual similarity analysis to strengthen protection against phishing.

BrowseBlock adopts the concepts of login-page identification, detection of deceptive authentication interfaces, and browser-level warnings from this research for its credential-harvesting detection module. The module can examine accessible webpage information, including credential-related form fields, submission destinations, URL characteristics, and inconsistencies between the displayed identity and the actual domain, to identify potentially fraudulent login pages. Visual similarity analysis could provide an additional detection signal if implemented and evaluated in BrowseBlock. The project adapts these relevant detection concepts without requiring the complete Page Transparency infrastructure, including its public log server and custom HTTP header. The resulting findings can be combined with URL analysis to assess suspicious login pages and provide users with warnings before they disclose sensitive credentials.
